===================
COMMAND: mdd_search
===================

1. Information
2. Patterns
3. Notes
4. Usage examples
5. See also

------------------------------------
search <pattern> [<pattern> ...]
mdd_search <pattern> [<pattern> ...]
------------------------------------

--------------
1. Information
--------------
Finds cvars and commands by name, by engine description and by help text.

Searches four things, in this order:

1. The names of ALL cvars the client knows: the engine's (cg_, r_, cl_, m_, ...), defrag's (df_, ...) and the proxymod's (mdd_). Printed with their current values.

2. The names of ALL commands, including +buttons.

3. The descriptions of engine cvars: the line the engine prints under the value when you type a cvar without one (\m_side). Each hit shows the cvar, its current value and the description. A cvar is listed here when its name or its description matches.

4. The help files in defrag/system/help: defrag's own and the proxymod's. Each hit shows the file name and the first matching line; "? <name>" shows the whole file.

"search" and "mdd_search" are the same command.

Added: 2026-11-24

-----------
2. Patterns
-----------
* is any run of characters (including none), ? is exactly one character, [a-z] is one character out of a set. Case does not matter. A pattern without any wildcard is searched as "contains": search mouse is search *mouse*. Several patterns can be given at once (up to 8); put a phrase in quotes: search "mouse moves".

In names a pattern starts at the beginning of the name and is open at the end (cg_*time also lists cg_drawTimer; nothing is missed, you can only get extra). In descriptions and help text it matches anywhere in a line.

--------
3. Notes
--------
The engine gives a cgame no way to list cvars or commands, read a description or list a folder, so:

Names (1, 2) come from the engine's own cvarlist and cmdlist run with your pattern. The letters in front of each cvar are cvarlist's flags (S serverinfo, U userinfo, R rom, I init, A archive, L latch, C cheat). A command the server interprets shows up only if the client registered its name for tab completion.

Descriptions (3) are a copy of oDFe's, built into the DLL. Engine cvars that oDFe gives no description (m_accel, for example) have none here either, and on another engine the texts are still oDFe's. Cvars of defrag itself have no descriptions; their documentation is the help files.

Help files (4) are opened by name from a list built into the DLL: every proxymod help file and the ones DeFRaG 1.91.31 ships. A help file you add yourself under another name is not searched.

-----------------
4. Usage examples
-----------------
search mouse
    Everything about the mouse: m_ and cl_mouse cvars by name, plus every description and help line that mentions it.

search cg_*time
    Every cg_ cvar or command with "time" after the prefix: cg_centertime, ...

search cg_crosshair*
    Everything that starts with cg_crosshair.

search *_*time*
    Anything with an underscore followed somewhere by "time".

search "mouse moves"
    A phrase: only the descriptions of m_pitch, m_forward and m_side contain it.

search +mdd*
    All proxymod hold buttons.

search overbounce
    Which of your tools and which defrag settings deal with overbounces.

search r_*gamma* cg_draw?d*
    Two patterns in one go.
